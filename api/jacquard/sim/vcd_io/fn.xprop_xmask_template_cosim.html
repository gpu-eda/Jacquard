X-mask template for the reactive cosim path (#95 phase 3).

Same as xprop_xmask_template but ALSO marks every primary-input position as X: in a reactive run an input is undriven until a model / clock / reset / constant drives it, so it starts unknown. state_prep clears the X-mask of each bit it drives every edge, so genuinely-driven inputs resolve to known while truly-undriven ones stay X. (The matching cone-analysis flag is DesignArgs::xprop_undriven_inputs, which makes those input cones X-capable so the kernel actually reads the input X-mask.)
